# W35 Core-defect record — Freeze stage validator misclassifies Human approval provenance as Stage Checkpoint

Status: `BLOCKED / SHARED_CORE_DEFECT / DEFERRED_MAINTENANCE`
Date: `2026-09-15Z`
Edition: `2026-W35`

## Summary

During W35 Freeze closure, the compatibility `survey_publication_v2.build_freeze()` path successfully generated a valid Freeze Record and Release Manifest, but the normal Freeze stage validator failed before evaluating those artifacts.

`survey_stage_validation_v2._prior_artifacts()` iterates every non-null value in `production-state.json.checkpoint_provenance` and validates each referenced file against `schemas/stage-checkpoint-v2.schema.json`.

After canonical Human Publication Preview approval, `checkpoint_provenance.publication_preview` legitimately references the Publication Preview approval JSON, not a Stage Checkpoint. The validator therefore misclassifies the approval record as a Stage Checkpoint and fails because the approval JSON does not contain the Stage Checkpoint-required `artifacts` field.

## Reproduction

From the valid W35 `RELEASE_CANDIDATE` state after Publication Preview approval and with valid Freeze/Manifest files generated by `survey_publication_v2.build_freeze()`:

```text
survey_stage_validation_v2.py --state sources/2026-W35/production-state.json \
  --artifact freeze-record=.../freeze-record-v2.json \
  --artifact release-manifest=.../release-manifest-v2.json
```

fails with:

```text
prior Stage Checkpoint fails schemas/stage-checkpoint-v2.schema.json: $: 'artifacts' is a required property
```

## Internal inconsistency

- `validate_agent_state` correctly treats Publication Preview provenance as Human approval authority.
- `_prior_artifacts()` instead assumes every `checkpoint_provenance` entry is a Stage Checkpoint.
- `stage-checkpoint-v2.schema.json` correctly requires `artifacts` for actual Stage Checkpoints.

Therefore controller and validator disagree about the semantic type of `checkpoint_provenance.publication_preview`.

## W34 precedent

W34 Freeze provenance explicitly recorded the same boundary class as:

`survey_stage_validation_v2 with bounded Freeze/Human-Gate artifact admission correction`

The correction preserved all true prior Stage Checkpoints, excluded Human Gate approval provenance from Stage Checkpoint admission, and still validated the approval through the dedicated Human-Gate authority path.

## Deferred repair direction

Do not repair shared Core while the separate J-GAS refactor is analysing the W34-era frozen Core baseline.

Later reviewed repair should make `_prior_artifacts()` distinguish true Stage Checkpoint provenance from Human Gate provenance, ideally by deriving eligible provenance keys from lifecycle/checkpoint producer metadata rather than iterating every non-null pointer.

Regression coverage should include `RELEASE_CANDIDATE` with canonical Publication Preview approval and prove the normal Freeze validator reaches and validates the Freeze/Manifest artifacts.

W35 may use the existing W34 bounded runtime-only admission correction as an edition-local closure precedent. No shared-Core byte change is required for that compatibility closure.
