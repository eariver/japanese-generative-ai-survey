本号について

    本号は、中国発の Generative AI を一つの技術潮流として平板化せず、GLM、Qwen、DeepSeek、Kimi の 4
系統をそれぞれの version-specific な一次資料から追う Thematic Special である。MiniMax、Yi、Baichuan は、
4 系統だけでは捉えきれない並行線・歴史的 bridge として扱い、Open Weight は技術仕様ではなく distribution
と権利条件を分けて読む。

    Scope / attribution boundary

    調査・記述の as-of boundary は 2026 年 8 月 22 日。後発 version の性質を過去 version へ遡及して帰属し
    ない。
    vendor / project / author が報告する性能・効率値は、記載された artifact と条件に限定して帰属する。異
    なる benchmark や serving stack を横断した勝敗表には再構成しない。
    community 由来の観測は調査上の手掛かりとして保持するが、一次資料による裏付けのない runtime 性能、
    普及度、license 解釈を技術的事実へ昇格させない。
    Open Source と Open Weight を同義語として扱わず、weights、code、license、commercial conditions、
    Model-as-a-Service 条件を artifact 単位で区別する。

8     4 系統は何に収斂し、どこで分岐したか

    CROSS-FAMILY SYNTHESIS

GLM、Qwen、DeepSeek、Kimi は 2026 年までに reasoning、coding/tool use、agentic workload、long context、
serving efficiency という似た課題へ接近した。しかし収斂しているのは problem set であって、implementation
recipe ではない。GLM は ARC と long-context serving、Qwen は family-wide hybrid reasoning と agentic coding、
DeepSeek は MLA/MoE efficiency と reasoning RL、Kimi は long-context RL から agentic MoE・native multimodal
へ進んでいる。 [6, 7, 9, 10, 11, 12, 14, 15, 16]

distribution についても一様ではない。Qwen3/Qwen3.6 は Apache-2.0 public/open-weight distribution を明示
し、GLM は version ごとに model-use/commercial permission と repository code の境界を確認する必要がある。
Kimi は K2/K3 の technical distribution と K3 固有 license を分離し、DeepSeek も native/distilled model subject
を混同しないことが重要になる。 [4, 9, 10, 12, 15, 16, 20]

したがって cross-family comparison は benchmark score を一枚の順位表へ畳み込むのではなく、各 family がどの
layer を競争軸へしたかを比べる方が再現可能である。architecture、post-training、serving、distribution/license
を別 dimension として見ることで、近い capability vocabulary の背後にある技術経路の違いを保持できる。 [6,
9, 11, 12, 14, 15, 20]
